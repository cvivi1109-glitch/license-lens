# 选题落地指南：换题目时该改哪些地方

`starter-repo` 现在的名字是 **license-lens**。如果你最终选了别的题目，
不需要重建仓库 —— **骨架（工程结构、许可证、模板、CI、脚本）全部可复用**，只需要替换核心逻辑。

---

## 一、必须改的地方（约 15 分钟）

| 文件 | 改什么 |
|------|--------|
| `license_lens/` 目录名 | 改成你的包名（例如 `simcheck/`），全小写、下划线分隔 |
| `pyproject.toml` | `name`、`description`、`keywords`、`[project.scripts]` 的命令名、`[tool.setuptools] packages` |
| `README.md` | 标题、一句话简介、特性、使用示例（**换成你的真实命令与输出**） |
| `license_lens/__init__.py` | `__version__` 与包说明 docstring |
| `tests/` | 换成你自己核心逻辑的测试（**别删，测试是 25% 分数的证据**） |
| `examples/` | 换成你的示例输入 |
| `CHANGELOG.md` | 保留文件，把 `[0.1.0]` 的内容改成你的功能 |
| `RELEASE_NOTES_v0.1.0.md` | 同上 |
| `docs/设计说明.md` | 换成你的问题定义与架构（**这篇对应 20% 汇报分**） |

全局替换包名最省事的做法：VS Code 里 `Ctrl+Shift+H`，把 `license_lens` 替换成你的包名。

---

## 二、可以直接留着不动的（脚手架价值）

| 文件 | 为什么留着 |
|------|------------|
| `LICENSE` | MIT 是工具/作业首选，换题也适用（只改年份/作者如有需要） |
| `.gitignore` / `.gitattributes` | Python 通用，照用 |
| `CONTRIBUTING.md` | 结构通用，只需改"新增许可证/新增规则"那两节的名字 |
| `.github/ISSUE_TEMPLATE/*` | 通用模板，照用 |
| `.github/PULL_REQUEST_TEMPLATE.md` | 照用 |
| `.github/workflows/ci.yml` | 只需确认 Python 版本与测试命令 |
| `scripts/init_repo.ps1` | 只需改提交内容清单（commit 的分组） |
| `docs/推送与首个Release指引.md` | 通篇通用，只改仓库名 |

---

## 三、按选题给的最小改动清单

### 若选「选题二：simcheck 代码相似度检测」
- 包名 → `simcheck`
- `licenses.py` + 规则引擎 → 换成 `SourceParser`（协议）+ `PythonParser` 实现
- `core.py` 的 `RULES` → 换成 `SimilarityStrategy` 列表（token 级 / AST 级）
- CLI 子命令建议：`compare <a.py> <b.py>`、`scan <dir>`、`report <a> <b> --html out.html`
- 测试重点：归一化后的 token 序列比较、阈值边界、空文件/语法错误文件

### 若选「选题三：repro-pack 实验可复现打包」
- 包名 → `repro_pack`
- `licenses.py` + 规则引擎 → 换成 `Collector`（协议）+ 文件/环境/版本控制三类实现
- `core.py` 的 `RULES` → 换成 `COLLECTORS` 列表 + `Manifest(schema_version=...)`
- CLI 子命令建议：`pack <dir>`、`verify <archive>`、`show <archive>`
- 测试重点：哈希一致性、篡改一个字节必须能检出、清单 schema 版本兼容

---

## 四、换题后必须重新做的一件事

**重新跑一遍验收，并把真实输出更新到 `docs/验收记录.md`。**

互评的第一条就是"按文档能否跑通"——README 里的每条命令都必须是你亲手跑过、能出对应输出的。
复制别人输出、或写了没跑过的命令，是互评最容易翻车的地方。
